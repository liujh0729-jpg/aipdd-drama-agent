# Motion feature film (MG)

> Pick a case from the gallery → the model writes a single-file MG page against the **render contract** → the local Chrome renders it frame by frame into an mp4, with a score generated by code → the per-shot outputs are assembled into a draft that opens in Jianying / CapCut.
> **Nothing leaves the machine, no third-party draft library, no VectCut service** — the desktop form has no service container, so this is the only deliverable path that actually works for desktop users.

Variables are listed in the [Environment Variable Reference](../reference/environment-variables.md#motion-feature-film-mg); binary selection and licensing in the [ffmpeg guide](ffmpeg.md#the-ffmpeg-bundled-with-the-desktop-app-measured).

## 1. Why three stages

| Stage | Problem it solves | Where it lives |
|---|---|---|
| **Gallery** | "What kind of film do I want" has to be visible first. 37 cases with category, duration, resolution, shot spec and the render contract | `src/novelvideo/freezone/motion_templates.json` + `motion_templates.py` (bundled fallback; swap catalogs with `MOTION_GALLERY_MANIFEST`) |
| **Render** | The model produces a moving web page, not a video file | `motion_render/`: a bootstrap takes over the clock, CDP captures frames, ffmpeg encodes them through `image2pipe` |
| **Delivery** | One render yields one shot; an editor needs the whole timeline | `motion_audio/` (score) + `motion_draft/` (Jianying 10.2 draft) |

Asset policy (posters bundled, originals on demand) is in the [Environment Variable Reference](../reference/environment-variables.md#motion-feature-film-mg): the 37 originals are ~0.7 GB and stay out of the installer.

## 2. How to use it

1. **Storyboard page → motion feature film**: open the gallery (posters are bundled, served locally); "use prompt" gives you that case's shot spec plus this system's render contract — the contract is stored once per catalog, so the prompt library, the gallery and the render task all read the same text.
2. **Generate MG per shot**: once the model produces the page, a render task is submitted (`POST …/freezone/motion/render`). Width/height, fps and duration are adjustable, as is the **score switch `music` (on by default)**. Progress: 0.12 page up → 0.94 frames → 0.95 arrange & normalize → 0.97 register asset.
3. **Export the Jianying draft**: `POST …/freezone/motion/draft` places the selected films in order on the main video track, turns each shot's self-reported beats into Jianying markers, optionally adds narration and a whole-film BGM bed, then copies the project into the local Jianying project directory.

Three files land next to each other: `<job>.mp4` (film, audio already muxed), `<job>.motion.json` (sidecar: duration, beats, audio outcome) and `<job>.score.wav` (normalized dry stem — use it when you want to ride the music volume separately in Jianying). The page `<job>.html` is kept too, so "why does this frame look like this" can be reproduced by opening it in a browser.

## 3. Where render-contract items 3 and 6 land

**Item 3 — lay the duration out on a beat grid first; cuts and key actions land on the grid; sound effects land on the frame where the action happens.**

- The page self-reports beats via `window.EV=[{t,type}]`. `motion_audio/grid.py` takes the **median inter-onset interval** as one beat, falls back to the case's stated BPM and then to 120, and folds the result into the audible 45–180 band (this resolves octave ambiguity: hitting every second beat yields 60, the grid should still run at 120).
- Phase is aligned onto the beats — for a beat-synced film the grid must pass through the action frames, otherwise "lands on the grid" is empty words.
- **Sound effects lead by one frame** (`TRANSIENT_LEAD_FRAMES = 1`): the picture draws the change on frame N, so the sound must already be audible when that frame is seen; landing on frame N is always one frame late (~33 ms at 30fps, which is enough to make the sync feel off). **Markers in the Jianying timeline still use the raw EV times** — two deliberately different references.
- Three arrangements only: `drive` / `pulse` / `ambient`, chosen by case category first (more specific categories are matched first, so a science explainer never gets a full drum kit) and tempo otherwise. Voices: kick/snare/hat/bass/pad/pluck plus impact/tick/riser, harmony Am–F–C–G.
- No sampled libraries: additive synthesis in numpy, FFT band shaping, envelopes, constant-power panning. **Bit-identical for the same inputs**, which is what makes snapshot tests meaningful — and keeps the desktop bundle free of both size and licensing questions.

**Item 6 — deliver audio at -14 LUFS with true peak no higher than -1 dBTP.**

- Two-pass `loudnorm` (EBU R128): pass one is `-f null`, measurement only; the five values from `print_format=json` are fed back verbatim into pass two with `linear=true`. Single-pass dynamic normalization pushes and pulls within a few seconds and is audible immediately.
- Muxing uses `-c:v copy -c:a aac -b:a 192k -shortest +faststart`, written to a temp file and swapped with `os.replace`: a cancelled job must not leave half a film behind.
- Measured (bundled LGPL ffmpeg, same page rendered twice): picture only = one `video/h264` stream; with score = `video/h264 + audio/aac`, before normalization `-15.47 LUFS / +0.01 dBTP`, **re-measured after muxing `-14.05 LUFS / -1.00 dBTP`**.
- The measured loudness facts are persisted in the sidecar (`audio.loudness`) so "why does this episode sound louder" is answerable.

**Failure must not sink the job**: when no usable ffmpeg is present or the arranger produces nothing, the render delivers a **silent film** and records `audio.engine = "silent"` with the reason (`off` means the submitter explicitly asked for picture only). A cancel signal is never swallowed by that fallback (`TaskCancelled` is neither `MotionAudioError` nor `OSError`).

## 4. What the Jianying draft looks like

Written from scratch — no pyJianYingDraft, no VectCut:

- Times are **integer microseconds**, paths use forward slashes, and both the root `draft_content.json` **and** `Timelines/<UUID>/` plus the mirror files are written, with `.locked` cleared — writing only the root file opens as an empty timeline in Jianying 9.x/10.x.
- Segments on one track may not overlap, so **video / narration / BGM get separate tracks**; whole-film narration and per-shot narration are mutually exclusive.
- The bundled 10.2 skeleton (`services/vectcut/template_jianying_10_2`) is checked before submission; if it is missing you get an immediate 409 with instructions rather than a broken draft on disk.
- **The embedded score ducks**: if the draft also contains narration, that clip's volume becomes 0.2; with only an external BGM, 0.35 (never 0 — delete the external bed in Jianying and the beat is still there). Silent renders are never ducked. The decision reads `audio.engine == "code-arranged"` from the sidecar; it is not a guess.

## 6. The three delivery forms

| Form | ffmpeg | Browser | Notes |
|---|---|---|---|
| **Docker / web** | image installs it via `apt-get` | you must provide one: `ST_CHROME_CDP_URL` (existing debugging instance) or `ST_CHROME_PATH` | the model-writes-the-page step needs `MODEL_PROVIDER` / `MODEL_API_KEY` |
| **Windows exe** | bundled `resources/bin/ffmpeg.exe` (BtbN **LGPL**, no `libx264`) | bundled `resources/bin/chrome/` | the launcher prepends `resources/bin` to the backend `PATH` and injects `APP_RESOURCE_PATH` |
| **macOS dmg** | ffmpeg from the build machine's `PATH` (usually Homebrew, includes x264) or `FFMPEG_BIN=` | bundled Chrome for Testing (`bundle.resources` now explicitly includes `resources/bin/chrome/**/*`) | identical Python logic, no platform branches; **the dmg itself is still unverified on a real machine** |

The render chain **never hardcodes `libx264`**: `src/novelvideo/video_encoder.py` probes `ffmpeg -encoders` and takes the first usable H.264 implementation from `libx264 → h264_videotoolbox → h264_mf → libopenh264`, so what reaches the editor or the platform is still H.264. That resolver is the only source of `-c:v` in the system — the episode composer and the `jobs.py` one-tap tools go through it too; see the [ffmpeg guide](ffmpeg.md).

## 7. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| "No usable Chrome found" | None of the three tiers hit: set `ST_CHROME_PATH` (executable) or `ST_CHROME_CDP_URL` (running instance). A path that does not exist is reported loudly, never treated as "no browser" |
| Result shows `audio.engine = "silent"` | No usable ffmpeg locally, or loudness normalization failed; a silent film was delivered. Reason is in `audio.error` — install ffmpeg (or set `FFMPEG_PATH`) and re-render that shot |
| "这一镜排不出配乐" / no score could be arranged | Illegal duration, or the page reports no beats and no grid can be inferred. Check the page's `window.DUR` and `window.EV` |
| Jianying opens an empty timeline | Jianying's own autosave overwrote the files, or the directory is incomplete: close Jianying → re-export → return to the home screen and reopen the project |
| 409 "bundled Jianying 10.2 draft template not found" | Incomplete package resources or a non-standard layout: set `MOTION_DRAFT_TEMPLATE_DIR`, or `NOVELVIDEO_PROJECT_ROOT` to the project root |
| Picture fine, nothing audible | That shot was delivered silent (check `audio.engine`), or the embedded score is ducked to 0.2/0.35 in the draft (remove the external BGM/narration track to restore it) |
