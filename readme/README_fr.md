## Qu'est-ce que DramaClaw ?

DramaClaw est une **chaîne de production open-source pour le drame IA** — et, de plus en plus, pour tout récit visuel que vous voulez créer avec des modèles génératifs. Elle a deux visages qui partagent une seule bibliothèque d'assets et un seul agent :

- **XiaHua — le canvas infini.** Un atelier à base de nœuds où vous générez, éditez et reliez librement images, vidéo, audio, décors 3D et scripts, puis remontez ce qui vous plaît dans la série. C'est là qu'aujourd'hui se fait l'essentiel de notre travail créatif, et c'est là que va DramaClaw.
- **Series (XiaJi) — le pipeline.** Déposez un manuscrit ou un scénario et DramaClaw prend en charge le gros du travail : structurer l'histoire, planifier les épisodes, écrire les scripts, dessiner les storyboards et les premières images, synthétiser la voix off, et monter le film final.

**Xia Director**, l'agent intégré, opère sur les deux : il répond aux questions sur votre projet, pilote les tâches du pipeline, et peut construire et exécuter des graphes de nœuds sur le canvas à votre place.

Conçu pour les créateurs, les studios indépendants et les ingénieurs créatifs — faites tourner toute l'« usine à drames » sur votre propre machine, sans assembler une douzaine d'outils déconnectés ni confier votre matériel à un service cloud opaque. Bien qu'il soit centré sur le drame, le même canvas et le même pipeline s'étendent aux publicités courtes, aux vidéos produits e-commerce et à d'autres formats visuels.

- **Outils vidéo** — texte / image / keyframe vers vidéo, génération à référence omnibus avec **références fichier, lien web et sur-canvas**, édition vidéo, effacement, upscale, séparation audio, templates caméra, analyse de plan ; Seedance 2.5 figure dans le catalogue recommandé

- **Skills canvas** — skills en un clic tels que croquis-from-context, image-from-context, décor-from-context, scene-360, revue d'image et planification de graphe de beats
- **Pensé pour les grands canvas** — onglets de canvas, plan des éléments, minimap et favoris de viewport, aimantation-alignment, rendu LOD, sélection multiple et nœuds de groupe, raccourcis clavier, historique de révisions avec restauration, verrouillage par canvas
- **Basculer vers la série** — prévisualisez l'impact, puis promouvez un nœud seul ou tout un lot dans la bibliothèque d'assets ou un épisode ; projetez la série sur un canvas depuis des préréglages

## Pourquoi DramaClaw ?

**Un canvas qui comprend le drame, et un agent qui y travaille.** Les canvais à nœuds génériques câblent tout mais ne savent rien des épisodes, personnages ou plans ; les outils de série connaissent le métier mais vous enferment dans un assistant. XiaHua vous donne le canvas libre avec des nœuds et skills conscients du drame, et Xia Director est construit pour disposer, exécuter et réviser ces graphes à votre place. Cette combinaison est la direction de DramaClaw.

**Pensé du roman à la mini-série.** Les outils de workflow génériques peuvent câbler des nœuds, mais ils ne savent pas ce qu'est un « beat d'épisode », ne comprennent pas pourquoi la cohérence d'identité d'un personnage à travers les scènes compte, et ne protègent pas l'arc émotionnel d'un chapitre à travers image + voix + montage. DramaClaw intègre tout ce jugement dans l'outil.

**Canvas et pipeline, pas canvas ou pipeline.** La plupart des outils donnent soit un canvas de nœuds libre, soit un assistant rigide. DramaClaw fait tourner les deux comme deux pistes jumelles sur une seule bibliothèque d'assets : explorez sur le canvas, basculez ce qui marche dans la série, projetez la série sur un canvas. L'agent travaille sur les deux.

**Chaque étape est décomposable.** Chaque stade est une tâche asynchrone indépendante avec sa propre interface. Enchaînez, sautez, reprenez à mi-chemin — la chaîne d'outils est le produit lui-même, sans boîte noire cachée.

**Auto-hébergeable, neutre en modèles.** Vos manuscrits, vos personnages, vos modèles, vos serveurs. Utilisez des modèles propriétaires de pointe quand vous voulez le meilleur ; basculez vers des modèles open-weight quand vous voulez le contrôle total. DramaClaw ne vous enferme chez aucun éditeur unique.

## Configuration requise

DramaClaw fait tourner toute l'inférence via une **passerelle compatible OpenAI** — soit le service de passerelle officiel DramaClaw, soit LocalNewAPI ([dramaclaw-gateway](https://github.com/dramaclaw/dramaclaw-gateway)) qui route vers les fournisseurs que vous configurez. Rien n'exécute de modèles sur votre machine, donc l'empreinte locale est légère. Un ordinateur portable ordinaire ou un petit VPS suffit.

| Élément | Exigence |
|---|---|
| **CPU / RAM** | ≥ 2 vCPU / 4 Go recommandé (hors inférence de modèles — elle tourne sur la passerelle) |
| **GPU** | Non requis pour le pipeline standard. Seul l'extra `world` optionnel (voxel / panorama-vers-3D) a besoin d'un GPU + image CUDA |
| **Disque** | Quelques Go pour les images plus les médias/état générés sous le volume `ce-data` (pas de minimum dur) |
| **OS** | macOS (Apple Silicon / Intel), Windows (Docker Desktop + backend WSL2), Linux (Docker Engine + plugin compose) |
| **Docker** | Docker + `docker compose` |
| **Ports** | `8080` UI web · `8780` API REST · `3000` UI admin LocalNewAPI (hôte-only par défaut, élargissable) |
| **Bases de données** | Aucune requise — pas de Postgres, Redis, Celery ni Ray. Les tâches tournent en-process ; l'état vit sur le système de fichiers local (SQLite + fichiers) |
| **Réseau** | Accès sortant vers la passerelle officielle `susciyuan.com`, et/ou vers les fournisseurs de modèles configurés dans LocalNewAPI |

> Le développement local (hors Docker) requiert en plus Python 3.11–3.12 + [`uv`](https://docs.astral.sh/uv/) + `ffmpeg`. Prérequis complets dans le [guide d'auto-hébergement](../docs/en/guides/self-hosting.md).

## <a name="démarrage-rapide"></a>Démarrage rapide

### Docker (recommandé)

Chaque Release GitHub publie des images multi-arch (amd64/arm64) sur Docker Hub.

**Build depuis les sources (par défaut)** — clonez DramaClaw et LocalNewAPI ([dramaclaw-gateway](https://github.com/dramaclaw/dramaclaw-gateway)) côte à côte ; `docker compose up -d --build` construit les trois services depuis ces deux checkouts.

```bash
git clone https://github.com/liujh0729-jpg/aipdd-drama-agent.git
git clone https://github.com/dramaclaw/dramaclaw-gateway.git   # LocalNewAPI, construit depuis ../dramaclaw-gateway
cd dramaclaw

cp .env.example .env
# Éditez .env — fixez PROMPT_EXPORT_PASSWORD à une valeur non par défaut.

docker compose up -d --build   # construit et démarre trois services : api / newapi (LocalNewAPI) / web
```

Les deux checkouts sont de simples repos git : éditez, `git pull`, recompilez. Seul le code DramaClaw a changé ? `docker compose up -d --build api web`. Seule la passerelle ? `docker compose up -d --build newapi`. Passerelle clonée ailleurs, ou vous préférez que Docker la récupère depuis git ? Fixez `DRAMACLAW_GATEWAY_SRC` dans `.env` vers ce chemin ou vers `https://github.com/dramaclaw/dramaclaw-gateway.git#main`.

**Sans build** — tirez les images publiées (pas de clone de la passerelle) :

```bash
docker compose -f docker-compose.release.yml up -d
```

Ouvrez l'app sur <http://localhost:8080> ; l'API REST est sur <http://localhost:8780>. Dans **Settings → Model Config**, choisissez l'un de :

- **Official** — collez votre clé DC (obtenez-en une sur <https://susciyuan.com>) ; aucune correspondance de modèles requise. LocalNewAPI reste inactif.
- **Custom** — un clic initialise LocalNewAPI ; ajoutez ensuite vos propres canaux amont.
- **LocalNewAPI + Official Hybrid** — officiel pour le pipeline principal, LocalNewAPI pour des canaux supplémentaires.

Étapes complètes dans le [Démarrage rapide](../docs/en/getting-started/quickstart.md).

Épinglez les versions ou changez de registre dans `.env` (`DRAMACLAW_VERSION`, `DRAMACLAW_GATEWAY_VERSION`, `DRAMACLAW_IMAGE_PREFIX`) — cela ne s'applique qu'au mode image (`docker-compose.release.yml`). Chine continentale : fixez `DRAMACLAW_IMAGE_PREFIX=claymore-registry.cn-chengdu.cr.aliyuncs.com/dramaclaw` et épinglez les deux versions (le miroir ACR ne porte que des tags épinglés).

> Vous migrez depuis un ancien checkout ? Pour le build source, d'abord `git clone https://github.com/dramaclaw/dramaclaw-gateway.git ../dramaclaw-gateway` (la passerelle est désormais construite depuis ce checkout voisin ; sans elle le build s'arrête avec `unable to prepare context`). `docker-compose.selfhosted.yml` / `docker-compose.selfhosted.release.yml` ont été supprimés — utilisez `docker-compose.yml` (build source) / `docker-compose.release.yml` (images). Les noms de services et les volumes `ce-data` / `newapi-data` sont inchangés ; les données existantes sont réutilisées telles quelles. Le port de LocalNewAPI ne se lie plus qu'à `127.0.0.1` par défaut ; fixez `ST_NEWAPI_BIND=0.0.0.0` dans `.env` si vous devez y accéder à distance.

### Développement local (uv + Python 3.11+)

```bash
git clone https://github.com/liujh0729-jpg/aipdd-drama-agent.git
cd dramaclaw

uv sync
cp .env.example .env && $EDITOR .env

uv run novelvideo api --port 8780   # démarre l'API REST (CE par défaut en tâches inline, sans Ray/Redis)
```

Frontend dans un second terminal : `cd frontend && pnpm install && pnpm dev`.

**Passerelle.** En mode **Official**, vous n'avez besoin de rien d'autre. En mode **Custom** ou **LocalNewAPI + Official Hybrid**, l'API attend une passerelle sur `127.0.0.1:3000` dont le fichier SQLite est `./state/newapi/one-api.db` (c'est là qu'« Initialize » dans les Settings écrit ; `NEWAPI_ADMIN_BASE_URL` dans `.env` y pointe déjà). Démarrez l'image publiée avec ce répertoire monté :

```bash
mkdir -p state/newapi
docker run -d --name dramaclaw-gateway -p 127.0.0.1:3000:3000 \
  -v "$PWD/state/newapi:/data" \
  claymorelab/dramaclaw-gateway:v1.0.0-rc.24-dramaclaw.1
```

ou lancez la passerelle depuis les sources dans le checkout voisin (`make dev-api` / `make dev-web` dans [dramaclaw-gateway](https://github.com/dramaclaw/dramaclaw-gateway#develop), ou `go build` et démarrez le binaire avec `SQLITE_PATH=<path to>/dramaclaw/state/newapi/one-api.db`).

## Modèles & fournisseurs pris en charge

DramaClaw reste neutre en modèles — tous les modèles texte / image / vidéo / audio se connectent via une **passerelle compatible OpenAI**. Choisissez le mode dans **Settings → Model Config** :

- **Official (recommandé)** — collez votre clé DC (obtenez-en une sur <https://susciyuan.com>), enregistrez, terminé. La passerelle officielle fournit déjà toutes les correspondances de modèles dont DramaClaw a besoin ; rien à configurer.
- **Custom** — un clic initialise LocalNewAPI, puis ajoutez vos propres canaux fournisseurs (clés API, IDs de modèles) dans son UI d'admin. Chaque modèle appelé par DramaClaw passe par vos canaux.
- **LocalNewAPI + Official Hybrid** — gardez les modèles officiels pour le pipeline principal et ajoutez des canaux (par exemple un workflow vidéo ComfyUI local) via LocalNewAPI.

> 🧠 **Apportez votre propre calcul — moins cher, mieux maîtrisé.** La passerelle est conçue pour que *vous* choisissiez où s'exécute chaque génération :
> - **Calcul inactif d'AIPDD (réduction des coûts).** Connecter le canal **AIPDD** permet à la génération de tourner sur le **pool de calcul inactif** de la plateforme ; les tâches lourdes de séries par lot ne coûtent qu'une fraction du prix à la demande — le levier le plus efficace pour baisser le coût de production. Inscrivez-vous sur <https://www.aipdd.work> pour obtenir une clé API AIPDD, puis ajoutez-la comme canal dans **Paramètres → Configurer les modèles**.
> - **NewAPI, combinez librement.** La passerelle **NewAPI** intégrée vous laisse enregistrer plusieurs fournisseurs comme canaux et **les combiner comme vous voulez** — officiels, AIPDD, une machine auto-hébergée, ou tout endpoint compatible OpenAI — par modèle, par étape. Pour les canaux NewAPI, nous recommandons de **chercher vos propres fournisseurs et de comparer les prix** ; une liste de référence sélectionnée est ici : <https://aiworkin.feishu.cn/wiki/F2WUwonOjikoDHkg1ERcDuPqnjf?from=from_copylink>.
> - **ComfyUI, sur votre propre GPU.** Un adaptateur **ComfyUI** de premier plan route la génération image / vidéo vers un workflow tournant sur **votre machine** : c'est votre matériel qui rend, sans quota cloud par appel. Enregistrez votre endpoint ComfyUI local comme canal en mode **Custom** ou **Hybrid**.

Parcours complet dans [Configurer les modèles](../docs/en/getting-started/configuring-models.md).

### LocalNewAPI : dramaclaw-gateway

Le service `newapi` de `docker-compose.yml` est [**dramaclaw-gateway**](https://github.com/dramaclaw/dramaclaw-gateway), le fork propre de DramaClaw de [New API](https://github.com/QuantumNous/new-api). Il parle le contrat **DC-Media** que DramaClaw utilise pour l'image / la vidéo / l'audio (rôles média, références, premières / dernières images) et convertit chaque requête dans l'API native du fournisseur. Image : [`claymorelab/dramaclaw-gateway`](https://hub.docker.com/r/claymorelab/dramaclaw-gateway) sur Docker Hub, épinglée par `DRAMACLAW_GATEWAY_VERSION` dans `.env`. Elle reste inactive en mode Official et n'est utilisée qu'une fois passé en **Custom** ou **LocalNewAPI + Official Hybrid**.

Adaptateurs fournisseurs livrés aujourd'hui dans la passerelle (voir la [matrice de support des canaux](https://github.com/dramaclaw/dramaclaw-gateway/blob/main/docs/providers/en/README.md) pour le statut de vérification) : ComfyUI · MiniMax H3 / Hailuo · VolcEngine Doubao / Seedance · Alibaba · Kling · Jimeng · Vertex AI · Gemini · OpenAI / Sora · Suno. Vous voulez un autre fournisseur ? La passerelle a un [générateur de squelette et un guide de contribution](https://github.com/dramaclaw/dramaclaw-gateway/blob/main/CONTRIBUTING.md).

| Étape             | Mode Official                              | Mode Custom / Hybrid (LocalNewAPI)                    |
|----------------------|----------------------------------------------------|-----------------------------------------------------------|
| **Texte / LLM**  | modèles `DC-*-LLM`, aucune correspondance       | tout canal chat compatible OpenAI                        |
| **Image**        | gpt-image · nano-banana                            | tout canal image enregistré dans la passerelle           |
| **Vidéo**        | Seedance série 1.0 / 1.5 / 2.0 · happyhorse       | tout adaptateur vidéo DC-Media (Seedance, Hailuo, Kling, ComfyUI, …) |
| **Voix off**     | IndexTTS2                                          | tout canal audio enregistré dans la passerelle           |
| **Graphe narratif** | Cognee (`DC-cognee-embedding`)                     | tout canal d'embedding                                  |
| **Runtime tâches** | inline en-process (sans Ray / Redis / Celery)      | identique                                                 |
| **Stockage**       | système de fichiers local                          | identique                                                 |

## <a name="in-development"></a>En développement

Ces éléments sont construits au grand jour et ne sont pas encore dans une release. Surveillez les branches, ou venez aider.

- **Xia Director sur le canvas** — l'agent crée et relie les nœuds, met à jour les données, dispose et groupe les nœuds, exécute les actions et construit des graphes de workflow entiers, chaque commande canvas étant d'abord approuvée dans le navigateur ouvert.
- **Catalogue de workflows & skills communautaires** — un catalogue de 11 skills de workflow et 60 recettes (drame, pubs e-commerce, pubs personnage IP, campagnes sociales, styles animé / Pixar / LEGO / kung-fu…) qui posent des graphes de génération complets ; skills et recettes sous forme de bundles installables, exportables, partageables
- **agent-kit** — un package portable qui apporte les mêmes workflows DramaClaw à Hermes, OpenClaw, WorkBuddy, Claude Code et Codex
- **Scène Previz** — une scène de blocage 3D dans le navigateur en tant que nœud canvas : timeline multi-pistes, rigs et chemins de personnages, modèle caméra objectif / capteur réel, suivi gros plan, puis capture du plan cadré directement dans le nœud suivant. Branche : `feat/previz-canvas-node`
- **Récits interactifs** — points d'embranchement sur le canvas, compilés en une histoire ink et exportés en lecteur HTML autonome, avec statistiques de playtest et couverture de chemins. Branche : `feat/canvas-fmv`
- **Publicités interactives** — les skills et recettes pub ci-dessus, combinés à la lecture à embranchements, pour des vidéos produits que le spectateur peut orienter
