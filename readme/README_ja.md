## AIPDD-Agent-Claw とは？

DramaClaw は **AI ドラマのためのソース公開型プロダクションライン** —— そして、生成モデルで語りたいあらゆる映像作品へと、ますます広がっています。1 つの素材ライブラリと 1 つのエージェントを共有する、2 つの顔を持ちます：

- **XiaHua —— 無限キャンバス。** 画像・動画・音声・3D セット・脚本を自由に生成・編集・接続し、気に入ったものをシリーズへ戻すノードベースのワークベンチ。今も未来も、私たちの創作の多くはここで生まれています。
- **Series (XiaJi) —— パイプライン。** 原文や脚本を投入すると、DramaClaw が重い作業を引き受けます：ストーリーの構造化、エピソード計画、脚本執筆、絵コンテとファーストフレームの描画、ナレーション合成、そして最終カットまで。

内蔵エージェント **Director** はこの両方にまたがって存在します：プロジェクトについて答え、パイプラインのタスクを進め、キャンバス上でノードグラフを構築して実行することもできます。

クリエイター、インディーズスタジオ、クリエイティブエンジニアのために作られました。 いくつものばらばらなツールを継ぎ接ぎしたり、素材を不透明なブラックボックスのクラウドサービスに渡したりせず、"ドラマ工場" 全体を自分のマシンで回せます。ドラマを中心に作られていますが、同じキャンバスとパイプラインはショート広告、EC 商品動画、その他の映像フォーマットにもそのまま使えます。

<br/>

## <a name="what-we-added"></a>AIPDD フォークが追加したもの

私たちは DramaClaw の無限キャンバスを出発点に、その周りのスタックを再構築しました。**自己完結・マルチライセンスのソースビルド**（外部イメージゼロ、デフォルトでの外部送信ゼロ）を土台に、これを**エージェントで操作できるドラマ工場**にするための機能を重ねています。

**1 · 内蔵エージェント —— Director。** プロジェクトを読み込み、進捗を確認し、脚本 / -shot タスクを進め、成果物の完全性を監査し、パイプラインのジョブを駆動し、あなたの代わりにキャンバスのノードグラフを配置して実行します —— キャンバスへのすべてのコマンドはまずブラウザで承認されます。

**2 · 完全な MCP サーバー —— 約 100 ツール。**  하나의 stdio ブリッジ（`uv run`）がシステム全体を **Claude Code、Codex** およびあらゆる MCP クライアントに開放します —— ツール `aipdd_drama_*` + `vectcut_*`、loopback CE-owner または `st-` API key。[ガイド →](../docs/en/guides/mcp-claude-code.md)。内訳は次のとおり：

- **ワンタップ一括ツール（「ツールページ」）** —— 動画クローン、ショート動画のMIX、ホワイトボードアニメ、解説モーショーン動画、アイデアから動画へ（ひと言 → 完成動画）、声のクローンと合成、リップシンク、人物置換、商品置換、動画の透かし除去、画像の透かし除去、動画吹き替え、Douyin 抜き出し。
- **キャンバス生成动词** —— *画像*：生成 / 編集 / 再描画 / 外へ拡張 / 再ライティング / 高解像度化 / マルチビュー / テンプレート編集 / プロンプト逆算 · *動画*：テキストから動画 / 画像から動画 / オムニ参照 / 高解画度化 / 編集 / 延長 · *音声*：ボーカル・伴奏分離 / 音楽 · *テキスト*：生成 / 翻訳 / ストーリー脚本 / 動画脚本逆算 / メディアコピーライティング。
- **ワンタップ自動化とオーケストレーション** —— 自動の絵コンテ段階ドライバー（スタイル → 脚本 → 話数 → 絵コンテ → ファーストフレーム）、ビート範囲での一括 shot 動画 / スケッチ / 動画プロンプト、そして `manual` / `checkpoint` / `auto` の 3 モードを持つ `run_pipeline` オーケストレーター（実行状態 / キャンセル / 設定提案付き）。
- **Jianying / CapCut の下書き編集** —— VectCut サービスを通じて、絵コンテ・吹き替え・字幕を本物の編集下書きに組み立てます（13 の `vectcut_*` ツール）。

**3 · セルフホストのための重度の再設計。** DramaClaw ゲートウェイ（AGPL-3.0）、DA-2（Apache-2.0）、ml-sharp（Apple）は [`third_party/`](../third_party/README.md) 配下に**同梱**され、スタック全体をソースからビルドします。リモートのカタログ / リリースフィードへの呼び出しは、デフォルト開ではなく**オプトイン**になりました。

ひと言で：**AIPDD-Agent-Claw = DramaClaw のキャンバス + エージェント + 約 100 ツールの MCP 面 + 自己完結ビルド** —— 手動でも、プロンプトでも、別の AI エージェントからも駆動できるシステム。

## 中核となる機能

### XiaHua —— 無限キャンバス

<p align="center">
  <img src="../assets/xiahua-canvas.jpg" width="900" alt="XiaHua canvas: a 17-node short-film workflow that Director laid out and ran from one prompt"/>
</p>
<p align="center"><sub>Director（右）への 1 つのプロンプトが、キャンバス（左）上のこの 17 ノード・32 エッジのワークフローになりました：ブリーフィング → ストーリー方針 → キャラクターとセットのリファレンス → 5 カットのファーストフレーム → 5 カットの動画 → ナレーションと BGM → 最終カット。</sub></p>

- **1 つのキャンバスに 18 種類のノード** — アップロード、画像生成 / 編集、絵コンテ生成、脚本、ビート文脈、動画、動画合成、動画ストーリー、音声、スタイル、スキル、グループ、テキスト注釈、360° パノラマビューア、3D ワールド、エクスポートなど。自由に接続でき、各ノードが自身の生成履歴を持ちます。
- **画像ツール** — 生成、編集、再描画、アウトペイント、リライト、アップスケール、マルチビュー、テンプレート編集、プロンプト逆算、マーク検出；画像-to-画像用の **45 種のショートドラマルック・スタイルウォール**
- **動画ツール** — テキスト / 画像 / キーフレームからの動画生成、**ファイル・Web リンク・キャンバス内リファレンス**に対応したオムニリファレンス生成、動画編集、消去、アップスケール、音声分離、カメラテンプレート、カット分析；推奨カタログに Seedance 2.5 を収録
- **音声** — ボイスライブラリとリファレンスボイスを備えた音声合成、音楽生成
- **キャンバススキル** — 文脈からスケッチ、文脈からフレーム、背景セット、scene-360、フレームレビュー、ビートグラフ計画など、ワンクリックのスキル
- **大きなキャンバスのために設計** — キャンバスタブ、要素アウトライン、ミニマップとビューポートブックマーク、スナップ整列、LOD レンダリング、複数選択とグループノード、キーボードショートカット、復元付きリビジョン履歴、キャンバス単位のロック
- **シリーズへのコミット** — 影響をプレビューし、単一ノードも一括も素材ライブラリやエピソードへ昇格；プリセットからシリーズをキャンバスへ投影
- **Director World —— 空間的に整合したセット** — 画像 → 3D Gaussian Splat セットと scene-360 パノラマをキャンバスノードに：空間構造・キャラクターのブロッキング・カメラ配置を固定できる仮想セットで、同じロケーションがカットをまたいで整合します。3D ビューアでカットを決め、キャプチャし、次の生成の背景に使う

## なぜ AIPDD-Agent-Claw？

**ドラマを理解するキャンバスと、その上で作業するエージェント。** 汎用ノードキャンバスは何でも接続できるが、エピソード・キャラクター・カットについては何も知りません。シリーズツールは技法を知っているが、ウィザードに固定します。XiaHua はドラマ対応のノードとスキルを備えた自由なキャンバスを与え、Director はそれらのグラフを配置・実行・レビューするために作られています。この組み合わせこそ DramaClaw の向かう先です。

**小説からショートドラマへ。** 汎用ワークフローツールはノードを接続できますが、「エピソードのビート」が何かを知らず、キャラクターのシーン横断の一貫性为何重要かを理解せず、1 章の感情アークを画像 + 声 + 編集をまたいで守ろうとはしません。DramaClaw はそうした判断をツール自体に組み込みます。

**キャンバスとパイプライン、どちらか一方ではなく。** 多くのツールは自由なノードキャンバスか、硬いウィザードのどちらかしか提供しません。DramaClaw は 1 つの素材ライブラリ上の双軌道として両方を回します：キャンバスで探索し、うまくいったものをシリーズへコミットし、シリーズを再びキャンバスへ投影。エージェントは両方で作業します。

**すべてのステップが分解可能。** 各ステージは専用インターフェースを持つ独立の非同期タスク。順に実行、スキップ、途中で再開 —— ツールチェーン自体がプロダクトで、隠れたブラックボックスはありません。

**セルフホスト可能、モデル中立。** あなたの原文、あなたのキャラクター、あなたのモデル、あなたのサーバー。最高の結果が欲しいときはクローズドソースの最先端モデルを、完全な制御が欲しいときはオープンウェイトモデルへ。DramaClaw は特定ベンダーにロックインしません。

## システム要件

DramaClaw はすべての推論を **OpenAI 互換ゲートウェイ** 経由で実行します —— 公式 DramaClaw ゲートウェイサービス、またはプロバイダ構成でルーティングする LocalAPI ([dramaclaw-gateway](https://github.com/dramaclaw/dramaclaw-gateway))。モデルはあなたのマシンでは動かないため、ローカルの負荷は軽量です。通常のノート PC や小さな VPS で十分です。

| 項目 | 要件 |
|---|---|
| **CPU / RAM** | 推奨 ≥ 2 vCPU / 4 GB（モデル推論を除く —— 推論はゲートウェイ上で実行） |
| **GPU** | 標準パイプラインでは不要。必要なのはオプションの `world` エクストラ（ボクセル / パノラマ→3D）だけで、GPU + CUDA イメージを使用 |
| **ディスク** | イメージ数 GB + 生成されたメディア/状態（`ce-data` ボリューム配下。厳密な最小値なし） |
| **OS** | macOS (Apple Silicon / Intel)、Windows (Docker Desktop + WSL2 バックエンド)、Linux (Docker Engine + compose プラグイン) |
| **Docker** | Docker + `docker compose` |
| **ポート** | `8080` Web UI · `8780` REST API · `3000` LocalAPI 管理 UI（既定は host-only、拡張可） |
| **データストア** | 不要 —— Postgres、Redis、Celery、Ray なし。タスクはインプロセス実行、状態はローカルファイルシステム（SQLite + ファイル） |
| **ネットワーク** | 公式ゲートウェイ `susciyuan.com` へのアウトバウンドアクセス、および/または LocalAPI で構成するモデルプロバイダへ |

> ローカル開発（非 Docker）では追加で Python 3.11–3.12 + [`uv`](https://docs.astral.sh/uv/) + `ffmpeg` が必要です。完全な前提条件は [Self-hosting guide](../docs/en/guides/self-hosting.md) を参照。

## <a name="quick-start"></a>クイックスタート

### ワンクリック（macOS / Windows）—— とにかく動かしたい人向け

ターミナル操作は不要です。コードを取得し（clone または **ZIP をダウンロード**して解凍）、リポジトリ直下の 2 つのランチャーを**順番に**ダブルクリックします：

| | macOS | Windows |
|---|---|---|
| **1 · インストール** | `安装环境-Setup.command` をダブルクリック | `安装环境-Setup.bat` をダブルクリック |
| **2 · 起動** | `启动系统-Start.command` をダブルクリック | `启动系统-Start.bat` をダブルクリック |

- **インストール ランチャーがすべてを用意**：macOS では Xcode Command Line Tools → Homebrew → Colima（Docker VM）→ Docker CLI + compose、Windows では WSL2 → Docker Desktop。続いて `.env.example` から `.env` を生成し、`api` / `web` / ゲートウェイのイメージをソースから初回ビルドします（ゲートウェイは `third_party/dramaclaw-gateway` に同梱済みなので、レジストリからは何も取得しません）。**起動 ランチャー**はスタックを立ち上げ、サイトが実際に応答するまで待ち、ブラウザで <http://localhost:8080> を開きます。
- **各ステップは冪等** —— 失敗したら原因を直して再びダブルクリックすれば再開できます。成功するとウィンドウは自動的に閉じ、失敗则開いたままなので内容を確認できます。
- **macOS 初回起動**：Gatekeeper が無署名の `.command` をブロックすることがあります —— ファイルを右クリック → **開く**（または システム設定 → プライバシーとセキュリティ で許可）。
- **Windows**：「管理者として実行」は**しないでください**—— Docker Desktop はユーザー単位でインストールされ、昇格したウィンドウだとランチャーが見つからない場所に置かれてしまいます。（WSL の設定時に一時的なシステム同意が出ますが、これは想定内です。）
- **コード変更後の再ビルド**：`bash 启动系统-Start.command --rebuild`（macOS）/ `启动系统-Start.bat --rebuild`（Windows）。デフォルトのダブルクリックでは再ビルドしないので、常に高速です。

> この経路は `docker-compose.aipdd.yml` を使います：`api`、`web`、ゲートウェイはいずれもソースからビルド（ゲートウェイは同梱の `third_party/dramaclaw-gateway` から）、SQLite + プロセス内タスクで Postgres/Redis/Celery は不要、かつ**外部イメージは一切取得しません**。初回ビルドは低速回線で 40〜90 分かかることがあります（以降の起動は数秒）。ログインとモデル接続は [初回実行](#first-run) を参照。

### Docker（推奨）

すべての GitHub Release はマルチアーキ（amd64/arm64）イメージを Docker Hub へ公開します。

**ソースビルド（既定）** — DramaClaw と LocalAPI ([dramaclaw-gateway](https://github.com/dramaclaw/dramaclaw-gateway)) を並べて clone；`docker compose up -d --build` がその 2 チェックアウトから 3 サービスをビルドします。

```bash
git clone https://github.com/liujh0729-jpg/aipdd-drama-agent.git
git clone https://github.com/dramaclaw/dramaclaw-gateway.git   # LocalAPI, ../dramaclaw-gateway からビルド
cd dramaclaw

cp .env.example .env
# .env を編集 — PROMPT_EXPORT_PASSWORD をデフォルト以外に設定。

docker compose up -d --build   # 3 サービスをビルドして起動: api / newapi (LocalAPI) / web
```

両チェックアウトは通常の git リポジトリ：編集し、`git pull`、再ビルド。DramaClaw のコードだけ変わった？ `docker compose up -d --build api web`。ゲートウェイだけ？ `docker compose up -d --build newapi`。ゲートウェイを他所へ clone した、または git から取得させたい？ `.env` の `DRAMACLAW_GATEWAY_SRC` にそのパスか `https://github.com/dramaclaw/dramaclaw-gateway.git#main` を設定。

**ビルドなし** — 公開済みイメージを pull（ゲートウェイの clone 不要）：

```bash
docker compose -f docker-compose.release.yml up -d
```

<http://localhost:8080> でアプリを開き、REST API は <http://localhost:8780>。 **Settings → Models & Channels** で次から 1 つ選択：

- **Official** — DC キーを貼るだけ（<https://susciyuan.com> で取得）；モデルマッピング不要。LocalAPI は待機したまま。
- **Custom** — ワンクリックで LocalAPI を初期化；その後自分のアップストリームチャネルを追加。
- **LocalAPI + Official Hybrid** — メインパイプラインは公式、追加チャネルは LocalAPI。

完全な手順は [Quick Start](../docs/en/getting-started/quickstart.md)。

`.env` でバージョン固定やレジストリ切替が可能（`DRAMACLAW_VERSION`、`DRAMACLAW_GATEWAY_VERSION`、`DRAMACLAW_IMAGE_PREFIX`）—— これはイメージモード（`docker-compose.release.yml`）のみに適用。中国本土：`DRAMACLAW_IMAGE_PREFIX=claymore-registry.cn-chengdu.cr.aliyuncs.com/dramaclaw` を設定し両バージョンを固定（ACR ミラーは固定タグのみ）。

> 古いチェックアウトから移行中？ ソースビルドではまず `git clone https://github.com/dramaclaw/dramaclaw-gateway.git ../dramaclaw-gateway`（ゲートウェイは隣のチェックアウトからビルドされ、無いとビルドが `unable to prepare context` で停止）。`docker-compose.selfhosted.yml` / `docker-compose.selfhosted.release.yml` は削除されました —— `docker-compose.yml`（ソースビルド）/ `docker-compose.release.yml`（イメージ）を使用。サービス名と `ce-data` / `newapi-data` ボリュームは変わらず、既存データはそのまま再利用。LocalAPI のポートは既定で `127.0.0.1` のみにバインド；リモートアクセスが必要なら `.env` で `ST_NEWAPI_BIND=0.0.0.0`。

### クラウドホスト / VPS（Linux）—— 共有または公開デプロイ

Linux サーバー（自身の VPS やクラウドインスタンス）では、Docker Engine と `docker compose` プラグインで同じソースビルドのスタックを動かせます —— ディストリビューションのパッケージマネージャーか Docker 公式の Linux ドキュメントで導入した後：

```bash
# 1 · get the code and configure it
git clone https://github.com/liujh0729-jpg/aipdd-drama-agent.git
cd aipdd-drama-agent
cp .env.example .env
#    Edit .env: set ST_LOCAL_PASSWORD, PROMPT_EXPORT_PASSWORD and your model
#    keys / official DC key before you start.

# 2 · build & bring the stack up (api / newapi gateway / web, all from source)
docker compose -f docker-compose.aipdd.yml up -d --build
```

- **ポート。** `8080` Web UI · `8780` REST API · `3000` LocalAPI 管理面（デフォルトは `127.0.0.1` のみ）。`8080` の前に **TLS 付きリバースプロキシ**（Caddy / Nginx / Traefik）を置き、`8780` / `3000` は内部に留め、ファイアウォール / セキュリティグループでは `80` / `443` のみ開放します。
- **初回ビルドは余裕を持たせる** —— ホストに RAM ≥ 8 GB、ディスク ≥ 40 GB を確保してください。でないとフロントエンドのビルドが OOM で kill されます。
- **ログイン** は単一マシンアカウント `local`、パスワードは `ST_LOCAL_PASSWORD`（または初回起動時に `docker compose -f docker-compose.aipdd.yml logs api` に出力される使い捨てパスワード）。
- **マルチユーザー？** CE は設計上シングルオーナーです。複数ユーザーに提供するなら `ST_CE_MULTI_USER` を有効にし、その前に本物の認証 + HTTPS を置いてください。本番の完全な注意書きは [セルフホスティングガイド](../docs/en/guides/self-hosting.md)。

### ローカル開発（uv + Python 3.11+）

```bash
git clone https://github.com/liujh0729-jpg/aipdd-drama-agent.git
cd dramaclaw

uv sync
cp .env.example .env && $EDITOR .env

uv run novelvideo api --port 8780   # REST API 起動（CE は既定でインラインタスク、Ray/Redis なし）
```

フロントエンドは別のターミナルで：`cd frontend && pnpm install && pnpm dev`。

**ゲートウェイ。** **Official** モードでは他に必要なものはありません。**Custom** や **LocalAPI + Official Hybrid** では、API は `127.0.0.1:3000` にゲートウェイを期待し、その SQLite は `./state/newapi/one-api.db`（設定の "Initialize" がここに書き込む；`.env` の `LOCALAPI_ADMIN_BASE_URL` は既にここを指します）。ディレクトリをマウントして公開済みイメージを実行：

```bash
mkdir -p state/newapi
docker run -d --name dramaclaw-gateway -p 127.0.0.1:3000:3000 \
  -v "$PWD/state/newapi:/data" \
  claymorelab/dramaclaw-gateway:v1.0.0-rc.24-dramaclaw.1
```

または隣のチェックアウトでソースからゲートウェイを起動（[dramaclaw-gateway](https://github.com/dramaclaw/dramaclaw-gateway#develop) で `make dev-api` / `make dev-web`、または `go build` してバイナリを `SQLITE_PATH=<path to>/dramaclaw/state/newapi/one-api.db` で起動）。

## <a name="first-run"></a>初回実行と使い方

どのインストール経路を選んでも、アプリの立ち上がり方は同じです：

1. **UI を開く** <http://localhost:8080>（ワンクリック ランチャーが代わりに開いてくれます）。REST API は <http://localhost:8780>。ブラウザは `web` とのみ通信し、`web` が `api` へリバースプロキシします。
2. **ログイン。** `docker-compose.aipdd.yml` の構成は単一マシンログイン（アカウント `local`）を有効にします。
   - `.env` で `ST_LOCAL_PASSWORD` を設定していれば、アカウント `local` とそのパスワードでログインします。
   - 空のままならバックエンドはアカウントを作りません：最初の画面が**初期化フォーム**になり、ユーザー名と初期パスワードを自分で設定します。最初のアカウントがスーパー管理者になり、このフォームは二度と開きません。以降のユーザー追加は **設定 → ユーザー管理** です。
3. **モデルを接続** —— **Settings → Models & Channels** でいずれか 1 モードを選びます（詳細は [サポートするモデルとプロバイダ](#supported-models)）：
   - **公式** —— <https://susciyuan.com> の DC key を貼り付け。全モデルがすでにマッピング済みで、LocalAPI は待機のまま。
   - **カスタム** —— ワンクリックで LocalAPI を初期化し、その管理 UI にご自分のアップストリームチャネル（API key + モデル ID）を追加。
   - **LocalAPI + 公式ハイブリッド** —— 主パイプラインは公式、追加チャネルは LocalAPI。
4. **創作を始める** —— 同じアセットライブラリに通じる 2 つの入口：
   - **剧集パイプライン**：小説または脚本を投入（Fountain 対応）すると、AIPDD-Agent-Claw が話数の計画、脚本作成、絵コンテとファーストフレームの描画、吹き替え合成、最終動画のカットまで担います。各段階は**タスクセンター**内の独立タスク —— 順番に、スキップ、または任意のチェックポイントから再開できます。
   - **キャンバス**：無限キャンバスを開き、ノード（画像、動画、音声、脚本、3D セット……）をドラッグ / 接続して自由に探究し、気に入った結果を剧集へ格上げします。

最新化：**起動** ランチャーを再びダブルクリックで再起動。稼働中のスタックは `docker-compose -f docker-compose.aipdd.yml ps` で確認し、`... logs -f api` でログを追います。全手順は [プロダクトマニュアル](https://neo-flying.feishu.cn/docx/JGNTdsjJuo748TxJkxecoYs2nth) と [クイックスタート](../docs/en/getting-started/quickstart.md) を参照。

## <a name="supported-models"></a>サポートするモデルとプロバイダ

DramaClaw はモデル中立 —— すべてのテキスト / 画像 / 動画 / 音声モデルは **OpenAI 互換ゲートウェイ** 経由で接続。**Settings → Models & Channels** でモードを選択：

- **Official（推奨）** — DC キーを貼る（<https://susciyuan.com> で取得）、保存、完了。公式ゲートウェイには DramaClaw の必要な全モデルマッピングが用意済み；設定は一切不要。
- **Custom** — ワンクリックで LocalAPI を初期化、その後管理 UI で自分のプロバイダチャネル（API キー、モデル ID）を追加。DramaClaw が呼ぶ全モデルがあなたのチャネルを経由。
- **LocalAPI + Official Hybrid** — メインパイプラインは公式モデルを維持し、LocalAPI 経由で追加チャネル（例：ローカル ComfyUI 動画ワークフロー）を追加 。

> 🧠 **計算資源を自分で選ぶ — コスト削減、制御も維持。** ゲートウェイは、各生成をどこで実行するか *あなた自身* が選べるよう設計されています：
> - **AIPDD の遊休計算資源（コスト削減）。** **AIPDD** チャネルに接続すると、生成をプラットフォームの**遊休計算資源プール**上で実行でき、負荷の大きい短編ドラマの一括処理をオンデマンド価格の数分の一でこなせます —— 制作コストを下げる最大のレバーです。<https://www.aipdd.work> で登録して AIPDD API Key を取得し、**Settings → Models & Channels**でチャネルとして追加してください。
> - **NewAPI、自由に組み合わせ。** 内蔵の **NewAPI** ゲートウェイなら、多数のプロバイダをチャネル登録し、**思い通りに組み合わせ**られます —— 公式、AIPDD、自前のサーバー、任意の OpenAI 互換エンドポイント —— モデル別・工程別に。NewAPI チャネルは**自らプロバイダを探して価格比較**するのがおすすめ。選別済みの参考リストはこちら：<https://aiworkin.feishu.cn/wiki/F2WUwonOjikoDHkg1ERcDuPqnjf>。
> - **ComfyUI、自分の GPU 上で —— キャンバス生成を最も安く回す方法。** ファーストクラスの **ComfyUI** アダプタは、画像／動画生成を**あなたのマシン**で動くワークフローへ向けます。GPU が描画するので**コール単位のクラウド枠を消費せず**、重い生成は実質電気代だけで、あらゆるホスト型モデルより割安です。**Custom** または **Hybrid** モードでローカルの ComfyUI エンドポイントをチャネル登録してください。
>   - **ComfyUI を最速で入れる方法** —— 手動インストールも Python 環境も不要。当社が同梱する**コンピュートクライアント（算力客户端）**をダウンロードしてインストーラを実行するだけです：<https://aiworkin.feishu.cn/wiki/ShOuwFDdBimuqCkz2Oqcofwdnm7>。

完全な手順は [Configuring Models](../docs/en/getting-started/configuring-models.md)。

### LocalAPI: dramaclaw-gateway

`docker-compose.yml` の `newapi` サービスは、[New API](https://github.com/QuantumNous/new-api) の DramaClaw 独自フォークである [**dramaclaw-gateway**](https://github.com/dramaclaw/dramaclaw-gateway) です。これは画像 / 動画 / 音声のための **DC-Media** コントラクト（メディアロール、リファレンス、最初 / 最後のフレーム）を話し、各リクエストをプロバイダのネイティブ API へ変換します。イメージ：Docker Hub の [`claymorelab/dramaclaw-gateway`](https://hub.docker.com/r/claymorelab/dramaclaw-gateway)、`.env` の `DRAMACLAW_GATEWAY_VERSION` で固定。Official モードでは待機し、**Custom** や **LocalAPI + Official Hybrid** に切り替えて初めて使われます。

現在ゲートウェイに同梱のプロバイダアダプタ（検証状況は[チャネル対応マトリクス](https://github.com/dramaclaw/dramaclaw-gateway/blob/main/docs/providers/en/README.md)参照）：ComfyUI · MiniMax H3 / Hailuo · VolcEngine Doubao / Seedance · Alibaba · Kling · Jimeng · Vertex AI · Gemini · OpenAI / Sora · Suno。他のプロバイダが必要？ ゲートウェイには[スキャフォールド生成器と貢献ガイド](https://github.com/dramaclaw/dramaclaw-gateway/blob/main/CONTRIBUTING.md)があります。

| ステージ             | Official モード                                | Custom / Hybrid モード（LocalAPI）              |
|----------------------|----------------------------------------------------|-----------------------------------------------------------|
| **テキスト / LLM**   | `DC-*-LLM` モデル、マッピング不要                | あらゆる OpenAI 互換チャットチャネル                     |
| **画像**             | gpt-image · nano-banana                            | ゲートウェイ登録のあらゆる画像チャネル                   |
| **動画**             | Seedance 1.0 / 1.5 / 2.0 series · happyhorse       | あらゆる DC-Media 動画アダプタ（Seedance, Hailuo, Kling, ComfyUI, …） |
| **ナレーション**     | IndexTTS2                                          | ゲートウェイ登録のあらゆる音声チャネル                   |
| **ストーリーグラフ** | Cognee (`DC-cognee-embedding`)                     | あらゆる埋め込みチャネル                                 |
| **タスクランタイム** | インプロセス inline（Ray / Redis / Celery なし）   | 同様                                                     |
| **ストレージ**       | ローカルファイルシステム                           | 同様                                                     |

## <a name="in-development"></a>開発中

これらはオープンに構築中で、まだリリースに入っていません。ブランチを観察するか、手伝いに来てください。

- **キャンバス上の Director** — エージェントがノードを作成・接続し、データ更新、配置とグループ化、ノード実行、ワークフローグラフ全体構築。すべてのキャンバス操作はまず開いたブラウザで承認。
- **ワークフローカタログとコミュニティスキル** — ショートドラマ、EC 広告、IP キャラ広告、ソーシャルキャンペーン、アニメ / Pixar / LEGO / kung-fu スタイル… の 11 ワークフロースキルと 60 レシピのカタログ。インストール・エクスポート・共有できるバンドルとして。
- **agent-kit** — 同じ DramaClaw ワークフローを Hermes、OpenClaw、WorkBuddy、Claude Code、Codex へ持ち運ぶ移植可能なパッケージ。
- **Previz ステージ** — キャンバスノードとしてのブラウザ内 3D ブロッキングステージ：マルチトラックタイムライン、リグとパス、実レンズ / センサーのカメラモデル、接写追従、そして決めたカットを次のノードへ直接キャプチャ。ブランチ：`feat/previz-canvas-node`
- **インタラクティブストーリー** — キャンバス上の分岐選択点を ink ストーリーへコンパイルし、スタンドアロン HTML プレイヤーとしてエクスポート、プレイテスト統計とパスカバレッジ付き。ブランチ：`feat/canvas-fmv`
- **インタラクティブ広告** — 上記の広告スキルとレシピに分岐プレイバックを組み合わせ、視聴者が操作できる商品動画に。
