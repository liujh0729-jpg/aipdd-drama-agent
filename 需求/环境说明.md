# 环境说明（aipdd fork · 源码构建与本地开发）

> 目的：环境相关的事一次说清，不用反复折腾；日常时间花在代码上。
> 配套：`Dockerfile` 顶部「构建缓存纪律」注释是构建的权威说明，本文是全景版。
>
> **给只要跑起来的人：双击仓库根的两个文件就够了**（Mac 见 §7，Windows 见 §8）——
> Mac：《安装环境-Setup.command》+《启动系统-Start.command》
> Windows：《安装环境-Setup.bat》+《启动系统-Start.bat》
> 安装程序装齐全部依赖并构建首版镜像，装完自动关窗；启动程序一键起栈并打开浏览器。
> 本文其余部分是原理与手工命令。

## 1. 本机环境（当前实测）

| 项 | 现状 |
|---|---|
| 宿主机 | macOS（Apple Silicon），Docker 由 **Colima** 提供（无 Docker Desktop） |
| Docker 存储 | Colima VM 内 `/dev/vdb1` **25G**（镜像 / 容器 / 卷全在这里），构建前先确认余量 |
| Compose | brew 现装的是 **Compose v2 的独立二进制**（`docker-compose version` 实测 5.5.1，默认 BuildKit）；`docker compose` 子命令仍不可用（未装 CLI 插件），一律写 `docker-compose`（连字符） |
| 宿主 Python | uv + Python 3.12（`uv sync`） |
| 宿主 Node | 前端用 pnpm（corepack）；后端构建用的 nodejs/npm 是镜像内 apt 装的 |
| 网络 | 慢（实测 ~90kB/s），构建时间大头全在下载 |

## 2. 构建与部署（本 fork 路径）

编排文件：`docker-compose.aipdd.yml`（api + web 源码构建；newapi/vectcut 见文件内注释）。

```bash
# 构建（api、web 一起；只改了代码时通常分钟级）
# 注意：不要写 `build --no-ansi`——那是 v1 时代的写法，Compose v2 把它当未知 flag，
# 会在参数解析阶段就失败（实测：unknown flag: --no-ansi）。
docker-compose -f docker-compose.aipdd.yml build api web

# 起栈 / 应用新镜像（--no-build：只用已建好的镜像，绝不顺手重建）
docker-compose -f docker-compose.aipdd.yml up -d --no-build

# 日志
docker-compose -f docker-compose.aipdd.yml logs -f api
```

版本 tag：`.env` 的 `DRAMACLAW_VERSION`（以文件为准，本文不再抄具体号——抄一次就错一次）。改版本号只换 tag，**不影响构建缓存**。

## 3. 构建缓存纪律（最重要，违反就要全量重下）

Dockerfile 已按三段式分层（详见 Dockerfile 顶部注释）：

1. **第 1 段**（FROM ~ COPY LICENSES：基础镜像、uv、ENV、ffmpeg 系统包、依赖文件）——**不要改动这段任何指令文本**。改一个字，Docker 缓存全链失效；仅 ffmpeg 系统包一项在本机慢网下就要重下约 30 分钟。
2. **第 2 段**（git/nodejs/npm、splat-transform、uv 依赖、hermes、chrome-devtools-mcp）——只在 `pyproject.toml` / `uv.lock` 变化时才重建。
3. **第 3 段**（COPY src 起的业务代码）——日常改代码只重建这里：分钟级、零下载（项目本体 uv sync 只做 editable 链接）。

硬性纪律：

- **永远不要** `docker image prune`、也**不要** `docker rmi` 带 tag 的旧版本镜像。`<none>` 的 untagged 中间层就是构建缓存本体，删掉 = 下次全量重下。（本机曾误删 2.0.50/2.0.51 等旧镜像，缓存连带受损，教训。）
- 磁盘紧张时，只清 **Exited 的临时构建容器**（`docker ps -a` 里状态 Exited 的随机名容器，`docker rm <名字>`）。镜像与卷一律保留。
- 给 `uv sync` **不要加 `--no-cache`**（uv 的 --no-cache 不读缓存，会强制重下 hatchling 等隔离构建依赖，与「不下载」相反）。
- 磁盘实在不够时：先清 Exited 容器 → 再清无主卷（`docker volume prune` 需确认）→ 最后考虑给 Colima 扩容（`colima stop && colima start --disk 40`），**不要删镜像层**。

### 全量重建的下载时间写照（慢网 ~90kB/s）

| 环节 | 耗时 |
|---|---|
| apt ffmpeg + fonts-noto-cjk | ~30 分钟 |
| apt git + nodejs + npm | ~10 分钟 |
| uv sync 第三方依赖 | ~30 分钟 |
| npm 全局包 + hermes 等 | 几分钟 |

三段式落定后，以上只有 `pyproject.toml` / `uv.lock` 变化时才会再发生一次。

## 4. 日常开发（标准流程）

```bash
# 后端
uv sync                         # 宿主环境装/更新依赖
uv run pytest                   # 测试（全量约 4-5 分钟）

# 前端
cd frontend && pnpm run build   # 产物 dist/（跳过 tsc 的原因见 frontend/Dockerfile 注释）

# 改完要部署（只重建第 3 段）
docker-compose -f docker-compose.aipdd.yml build api web
docker-compose -f docker-compose.aipdd.yml up -d
```

## 5. 环境变量（本 fork 增量）

权威清单是仓库根 `.env.example`（逐项注释）。本 fork 额外键：

| 键 | 作用 |
|---|---|
| `ST_CHROME_CDP_URL` | 容器连宿主 Chrome 调试端口（默认 `http://host.docker.internal:9222`），Chrome MCP 与抖音文案提取用 |
| `HOST_HOME_PATH` | 宿主 home 映射进容器（`/host-home`），本地 Agent 工具用 |
| `DRAMACLAW_VERSION` / `VECTCUT_VERSION` | compose 里镜像 tag |
| `INSTALL_WORLD` | `1`=构建期装 3DGS/SHARP（world extra）；默认 0，运行时按需 |

## 6. 已知坑速查

| 现象 | 处理 |
|---|---|
| 构建提交层时 `no space left on device` | Colima 25G 卷满：清 Exited 临时容器；仍不够见 §3 纪律 |
| 重建突然变慢、开始下载 | 误动了第 1 段指令文本，或删过镜像/中间层（缓存被清） |
| `docker compose` 命令不存在 | 本机只装了独立二进制，用 `docker-compose`（连字符） |
| 构建时 splat-transform 报 `EBADENGINE` 警告（node 20 < 22） | Debian trixie 的 nodejs 是 v20，`@playcanvas/splat-transform` 新版要求 ≥22；仅警告、安装可用。若将来启用 world（PLY→SOG）报 node 版本错误，再升级镜像内 nodejs 或钉旧版 splat-transform |
| 8780/8080 被占 | `docker-compose -f docker-compose.aipdd.yml down` 后重起，或查端口占用 |

## 7. Mac 一键脚本（双击即可）

仓库根两个 `.command` + 共享层 `scripts/mac_common.sh`（两个入口的判断逻辑必须同源，各抄一遍必然漂移）。Finder 双击打开的 Terminal 是精简 PATH，不保证有 `/opt/homebrew/bin`，所以脚本自己补——这也是「终端里明明有 brew、双击却说找不到」的根因。

| 文件 | 做什么 | 结束行为 |
|---|---|---|
| `安装环境-Setup.command` | Xcode 命令行工具 → Homebrew → colima / docker / docker-compose → 首次创建虚拟机（cpu 4 / mem 8G / disk 40G，并挂载 `~:w` 与 `/Applications`）→ 缺 `.env` 时按 `.env.example` 生成 → 首版 api/web 镜像构建 + 预拉网关镜像 | 成功自动关窗；每步幂等，失败**停住不关窗** |
| `启动系统-Start.command` | 起 Colima → 等 Docker 守护进程可达 → 镜像缺则建 → `up -d --no-build` → 轮询站点 `/api/v1/config` 真就绪 → 打开浏览器 | 成功倒计时 8s 后关窗（服务在后台继续跑）；失败停住 |

要点（都是实测口径，动手改之前先读）：

- **就绪判定打真实接口，不看容器 `healthy`**：api 首启加载模型库要 87-250s，`healthy` 明显滞后；而只 curl 首页会因静态文件恒 200 假绿。走 web 端口的 `/api/v1/config` 一次验证 nginx + 反代 + 后端三截。
- **默认路径绝不擅自重建镜像**：双击启动只做 `up -d --no-build`（幂等，容器不会被无谓 recreate）。改过代码想生效用 `bash 启动系统-Start.command --rebuild`：先跑 `scripts/predeploy_backup.sh` 备份状态库 → 过 §3 空间闸门 → 重建 → 起栈。
- **虚拟机配额只在首次创建时设**：Colima datadisk 预分配，静默调大等于要求 macOS 立刻让出等量空间。已存在虚拟机时脚本只 `colima start`，要改口径必须手工停启。
- **`--mount` 是替换语义**：首次创建要同时给 `~:w` 与 `/Applications`，只给一条会顶掉默认的 home 共享，容器内 `/host-home`（本地 Agent 工具写 MCP 配置）随之失效。
- **compose 参数面**：Compose v2 下 `build` 不认子命令后的 `--no-ansi`（实测 `unknown flag`），一键脚本已去掉；`up -d --no-build` 在 v1/v2 都合法。
- 失败提示里不给危险命令：空间不足一律指回 §3 的清理口径（不删带 tag 的镜像与中间层，那是构建缓存本体）。
## 8. Windows 一键脚本（双击即可）

仓库根两个 `.bat` + `scripts/windows_common.ps1`（公共层）+ `windows_setup.ps1` / `windows_start.ps1`。与 §7 同构：入口薄、逻辑同源、就绪只打真实接口、失败停住给人看、成功才自动关窗。

| 文件 | 做什么 | 结束行为 |
|---|---|---|
| `安装环境-Setup.bat` | 系统自检 → WSL 2 → Docker Desktop（per-user）→ 拉起并等引擎 → compose 与宿主路径 → 缺 `.env` 时按 `.env.example` 生成 → api/web 源码构建 + 预拉网关镜像 | 成功即关窗（「装好自动退出」）；每步幂等，失败停住 |
| `启动系统-Start.bat` | 等引擎 → 镜像缺则建 → `up -d --no-build` → 轮询站点 `/api/v1/config` 真就绪 → 打开浏览器 | 成功关窗（容器在后台继续跑）；失败停住 |

编码与行尾是交付纪律，不是风格问题（`tests/test_windows_launchers.py` 会把破坏它的编辑直接判红）：

- `.ps1` 必须 **UTF-8 带 BOM + CRLF**：Windows PowerShell 5.1 读无 BOM 的 UTF-8 会按本地代码页解析，中文提示全成乱码。
- `.bat` 必须 **纯 ASCII + CRLF、不带 BOM**：cmd.exe 按控制台代码页逐行解析批处理，中文进 .bat 就是乱码，开头的 BOM 还会被当成第一条命令。所以所有中文文案都在 .ps1 里，.bat 只做 `chcp 65001` → `cd /d "%~dp0"` → 调 PowerShell → 按退出码决定是否兜底 `pause`。
- 退出码契约：`Wait-Here` 用 `exit 3` 表示「已自报原因并等人按过回车」，.bat 侧 `if %RC% GEQ 3` 就不再叠一个 `pause`（写错会让人按两次回车）。

外部命令口径（都取官方文档，别凭手感改）：

- `Docker Desktop Installer.exe install --user --quiet --accept-license --backend=wsl-2`。**`--user` 装进 `%LOCALAPPDATA%\Programs\DockerDesktop`，不需要管理员**；`--accept-license` 连带接受订阅协议，首启不再弹框。装完**不会自启**，所以脚本第 4 步必须自己拉起再等引擎。
- 许可阈值一次说清：Docker Desktop 对个人/教育及「<250 人且年营收 <1000 万美元」的小企业免费，超出需付费订阅（政府单位一律需要）。要走完全免费路线可换 Rancher Desktop / Podman Desktop，本脚本按 Docker Desktop 写。
- WSL 需 2.1.5+，`wsl --install --no-launch` 要提权（这是全程唯一一次 UAC），且**可能要求重启**；重启后重新双击即从当前进度续上。
- 不要「以管理员身份运行」：`--user` 会把 Docker 装进**当前进程所属账户**的 profile，管理员窗口里装的，普通用户双击启动时找不到 `docker.exe`。脚本第 1 步会探测并警告，第 3 步的失败提示也给了补救路径。

Windows 侧与 Mac 侧的三处真实差异：

- **宿主路径映射**：编排文件里 `${HOME}` 与 `${HOST_APPS_DIR:-/Applications}` 的默认值是 Mac 假设，Windows 上 `HOME` 通常没定义、`/Applications` 不存在，直接交给 bind mount 会变成古怪路径并触发文件共享提示。`Set-WindowsComposeEnv` 显式给成 `HOME=%USERPROFILE%`、`HOST_APPS_DIR=%LOCALAPPDATA%\Programs`（后者是 Windows 的用户级应用目录，正是本地 Agent 工具要看的「应用本体」证据位置），并保证目录真实存在。
- **per-user 安装写的用户 PATH，当前窗口读不到**：`Add-DockerToPath` 在脚本内补 `%LOCALAPPDATA%\Programs\DockerDesktop\resources\bin`，否则症状是「装完了却说没有 docker」（与 §7 的 Mac 精简 PATH 同一类坑）。
- **没有 bash**：`scripts/predeploy_backup.sh`（bash + 容器内 Python 的 sqlite Backup API）跑不了，所以 `Start.bat --rebuild` **不假装能在线备份**，改为说明风险并要一次 `y` 确认。双击默认路径永远走不到这里。

其它已收口的细节：

- compose 前缀自适应（优先 `docker compose` 插件，探不到才用 `docker-compose.exe`），打印给用户照抄的命令一律用实际存在的那个（`Get-ComposeHint`）。
- 取一次性口令用 `findstr ST_LOCAL_PASSWORD`，不用中文关键字：findstr 按当前代码页比对字节，GBK 控制台下拿中文去找 UTF-8 日志会匹配不到（同一条日志里两个 token 都在）。
- 就绪判定同 §7：打 web 端口的 `/api/v1/config`，一次验证 nginx + 反代 + 后端。首启可能弹「允许访问文件系统」，需要点允许（本项目要把用户目录挂进容器）。
- `ExecutionPolicy` 被组策略强推时，命令行的 `-ExecutionPolicy Bypass` 压不过机器级策略；.bat 在这种非零退出（且 <3）时会打一行指路 `Get-ExecutionPolicy -List`。

**实测状态（诚实口径）**：Mac 侧 §7 已在真机跑通（安装器 24s 全 skip、启动器多轮 + 双击等价路径、容器 ID 幂等）。Windows 侧本机没有 PowerShell 可执行环境，**未在真实 Windows 上跑过**；能做的静态验证已进守卫测试（编码/行尾、括号栈、命令名悬空、bat↔ps1 路径与退出码契约、多行提示里的 `1) 2) 3)` 不误报），参数面逐条有官方出处。首次真机验收建议顺序：第 1-4 步（WSL + Docker Desktop 起来）→ 单独 `docker compose -f docker-compose.aipdd.yml config` 看插值后的挂载 → 再放行第 7 步的构建。
